1) P2: Form a Valid Arithmetic Equation (Prolog, file id_q2.pl)
Given a list of non-negative integers, insert the operators +, -, *, / and exactly one = between the numbers
(using every number once, in the given order, with optional parentheses) so that both sides of the equation
have the same value.
• Let the list be n1, n2, ..., nk. An equation is L=R, where L is an expression over n1..nj and R is an
expression over n(j+1)..nk, for some j with 1 <= j < k. Every number is used exactly once, in order.

• An expression is a single number, or two expressions joined by one of + - * /, optionally in
parentheses. There is no unary minus, and digits of different numbers are never joined into a bigger
number. Values of sub-expressions may be negative (for example 3-5).
• Division is allowed only when it is exact (the result is an integer with no remainder) and the divisor is not
zero. This applies to every division inside an expression, not just the last.
• Both sides must have the same integer value.
Output format of an equation (canonical form)
An equation is returned as an SWI-Prolog string (not an atom, not a code list), with no spaces, for
example "4*2=5+3". Numbers are written in decimal. Parentheses are printed by this rule, which gives
every different expression tree a different string:
• * and / bind tighter than + and -.
• Operators are left-associative.
• A left operand is written in parentheses only if its top operator has lower precedence than its parent's.
• A right operand is written in parentheses if its top operator has the same or lower precedence than its
parent's.
• A single number is never in parentheses.
Examples of the rule: (4+2)*3, 4+2*3, 8/4*2 (this is (8/4)*2), 8/(4*2), 1-2-3 (this is (1-2)-3), 1-(2-3),
1+(2+3), 1+2+3 (this is (1+2)+3). Note that 1+(2+3) and 1+2+3 are different trees, so both count as
different equations.
Examples
• generate_equation([4,2,5,3], E) gives one of the seven equations below.
• all_equations([4,2,5,3], Es) gives ["4*2-5=3", "4*2=5+3", "4-2=5-3", "4/2=5-3",
"4=2*(5-3)", "4=2+(5-3)", "4=2+5-3"].
• generate_equation([2,3,4], E) fails, and all_equations([2,3,4], Es) gives Es = [].
• all_equations([2,4,8], Es) gives ["2*4=8"].
Constraints: no assert, retract or global variables. Do not build a string and parse it back into a term to
evaluate it. Allowed libraries: lists, apply, yall, aggregate. Do not print anything.

P2.a. generate_equation(List, Equation) unifies Equation with one valid equation for List. Any
valid equation is accepted. It must fail (not loop, not raise an error) if no valid equation exists, including
for lists of length 0 or 1.
